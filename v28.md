### A.4.4 Tính năng FB v31 mới AlumGlass tận dụng

FB v31 bổ sung các tính năng mới giúp AlumGlass giảm code, tăng linh hoạt:

| Tính năng FB v31 | Cách AlumGlass dùng | Lợi ích |
|---|---|---|
| **BatchBindingResolver** | B2 pre-fetch: gọi `resolver.resolve_all_batch(bindings)` thay vì 4-5 đoạn batch query rời rạc | Giảm 90% queries, code B2 từ ~85 dòng → ~30 dòng |
| **SourceTypeRegistry** | Đăng ký handler `aluminum_price_composite`, `glass_master_data`, `cost_bucket_aggregate` qua `hooks.py` | Không monkey-patch FB, auto-discovery, có metadata |
| **13 source types** | Cost Bucket dùng `doctype_query`, `pipeline`, `conditional`, `fallback_chain` thay vì code Python | User tự cấu hình Cost Bucket mới không cần dev |
| **JSON Schema validation** | Mỗi AL Cost Bucket có `source_config` được validate tự động | Chặn lỗi cấu hình sai từ UI |
| **Transform layer** | Đơn giá USD→VND, mm→m, làm tròn giá qua `transform` config | Giảm code Python xử lý hậu kỳ |
| **@batchable decorator** | Handler `aluminum_price_composite` được mark batchable → FB tự gom query | 8 dòng NHOM → 1 query thay vì 8 |
| **Composite types** | `pipeline`: base price → tax → margin; `conditional`: chọn giá theo product_type; `fallback_chain`: API → cache → default | Không code Python cho business logic phức tạp |

**Nguyên tắc:** AlumGlass là **lớp mỏng** (thin layer). Mọi thứ FB làm được thì dùng FB. AlumGlass chỉ code phần domain-specific (slug library, composite key nhôm kính, bom item structure).

# PHẦN B — MASTER DATA

## B.1 AL SLUG LIBRARY — HỆ THỐNG SLUG TẬP TRUNG

### B.1.1 Vai trò

AL Slug Library là **DocType quản lý slug tập trung**. Slug là mã định danh duy nhất
của một dòng trong BOM, được sử dụng làm khóa tham chiếu chéo (cross-row reference)
theo cú pháp: `<child_table>.<slug>.<field>`.

**Lợi ích:**
- Slug được khai báo **1 lần duy nhất**, dùng chung cho nhiều BOM, nhiều Bom Set
- Tránh lỗi gõ sai slug (kinh_tren vs kinhtren) — sai là không tra được
- Dễ maintain: đổi tên hiển thị ở 1 chỗ, không sửa từng Bom Set
- Là cơ sở cho `AL Slug Library` cho phép chọn slug từ dropdown ở AL Bom Item

### B.1.2 Cấu trúc AL Slug Library (Master)

| Fieldname | Fieldtype | Reqd | Mô tả |
|---|---|---|---|
| `slug` | Data | Y unique | Mã slug: `khung_ngang_tren`, `kinh_tren`, `nep_kinh_tren` |
| `label` | Data | Y | Tên hiển thị: "Khung ngang trên" |
| `line_type` | Select | Y | NHOM / KINH / VTP / PK |
| `group_tag` | Data | | Nhóm: KHUNG, CANH, NEP, KINH, GIOANG, VIT, PK |
| `description` | Small Text | | Mô tả chi tiết, hướng dẫn |

### B.1.4 Ràng buộc namespace của Slug

**Quy tắc:** Slug đã khai báo trong AL Slug Library với `line_type` cố định **chỉ dùng cho đúng loại đó**. 

- Nếu slug `kinh_tren` có `line_type=KINH` trong Library, thì mọi Bom Set muốn dùng slug này PHẢI dùng cho dòng KINH. Một BOM khác không thể dùng `kinh_tren` cho dòng VTP hay NHOM.
- Điều này đánh đổi giữa "dùng chung" và "ràng buộc type". Lý do: đảm bảo an toàn khi tham chiếu chéo — khi bạn viết `items.kinh_tren.width`, bạn biết chắc `kinh_tren` luôn là dòng KINH có field `width`.
- Để tránh đụng độ namespace giữa các nhóm sản phẩm, đặt slug theo convention: `{nhom_san_pham}_{vai_tro}` — VD: `cua_di_kinh_tren`, `cua_so_kinh_giua`.

**Khi nào cần slug mới?** Khi tạo sản phẩm mới có vai trò dòng chưa có trong Library. Không tạo slug trùng tên nếu `line_type` khác — hãy đặt tên mới (VD: `cua_lua_kinh_tren` thay vì tái dùng `kinh_tren` cho cửa lùa nếu khác biệt về nghiệp vụ).

## B.2 AL BOM ITEM — TRUNG TÂM HỆ THỐNG

### B.2.1 Vai trò

AL Bom Item là **DocType thống nhất duy nhất** cho mọi loại vật tư trong BOM:
NHOM (nhôm profile), KINH (kính), VTP (vật tư phụ), PK (phụ kiện).

Nó thay thế hoàn toàn AL Profile Line, AL Profile Set Line, AL PK Line
trong thiết kế v26/v27.

**Nguyên tắc thiết kế:**
- Slug lấy từ AL Slug Library (Link, không nhập text tự do)
- Tên field bỏ hậu tố `_formula`: `width`, `height`, `qty` (không `width_formula`)
- Công thức dùng cú pháp Formula Builder: `W_mm`, `$OFFSET_FRAME`, `items.kinh_tren.width`
- Field `formula_expr` (computed) được sinh tự động từ `width` + `height` + `qty` + `formula_set`
để FlexibleFormulaEngine có thể collect formulas.

### B.2.3 Field `formula_expr` — ⚠️ DEPRECATED

Trường này **không còn được sử dụng** trong v28.1. Trước đây nó được tính toán (server-side) khi lưu Bom Item để FlexibleFormulaEngine có thể collect toàn bộ công thức cho 1 dòng BOM qua `ChildTableConfig.formula_field`.

**Lý do bỏ:** Gộp nhiều công thức qua `; ` không tương thích với `ast.parse(mode='eval')`. Thay vào đó, mỗi field `width`, `height`, `qty` được giữ riêng và engine dùng `build_cross_ref_engine` path.

**Code cũ (đã deprecated, giữ lại để tham khảo):**

**Logic sinh:**

```python
def compute_formula_expr(doc, method):
    """Sinh formula_expr từ các field riêng lẻ."""
    parts = []
    if doc.width:
        parts.append(f"width: {doc.width}")
    if doc.height:
        parts.append(f"height: {doc.height}")
    if doc.qty:
        parts.append(f"qty: {doc.qty}")
    if doc.formula_set:
        # Lấy các công thức từ Formula Set (VD: BOM_LINE)
        fs = frappe.get_doc("Formula Set", doc.formula_set)
        for line in fs.formulas:
            parts.append(f"{line.var_name}: {line.formula}")
    return "; ".join(parts)
```

**Kết quả cho 1 dòng điển hình:**
```
width: W_mm - 2*$OFFSET_FIXED; height: TransomHeight_mm - $OFFSET_FIXED; qty: 1; so_luong_don_vi: lookup_calc_pattern(calc_pattern, width, height, trong_luong_rieng); tong_so_luong: so_luong_don_vi * qty; thanh_tien: tong_so_luong * don_gia
```

### B.2.4 Quy tắc field theo line_type

**NHOM (Nhôm profile):**
- `calc_pattern` = LENGTH_TO_WEIGHT
- `price_base_item` = Item đại diện (VD: NHOM-XINGFA)
- `item_code` = Profile cụ thể (VD: XF55-KB-20)
- Cần resolve thêm `trong_luong_rieng` từ `Item.weight_per_unit`

**KINH (Kính):**
- `calc_pattern` = AREA
- `price_base_item` = (không dùng, giá tính theo m2)
- Thêm field: `default_glass_master` (Link -> AL Glass Master)
- Thêm field: `ctx_inject_prefix` (Data, unique trong Bom Set)
- `glass_thick` và `glass_type` được inject tự động vào inputs từ AL Glass Master

**VTP (Vật tư phụ):**
- `calc_pattern` = LENGTH_ONLY hoặc COUNT
- `price_base_item` = (có thể có hoặc không)

**PK (Phụ kiện):**
- `calc_pattern` = COUNT
- `price_base_item` = (thường không có)
- `allow_substitute` = Check (cho phép thay thế PK)

```python
def validate_unique_price_combo(doc, method):
```

# PHẦN C — FORMULA ENGINE TÍCH HỢP

## C.1 KIẾN TRÚC 2 PATH CỦA FORMULA BUILDER

### C.1.1 Tổng quan

Formula Builder v30 cung cấp **2 đường dẫn (path)** để tính toán công thức:

| | Path A: FlexibleFormulaEngine | Path B: VariableResolver + build_cross_ref_engine |
|---|---|---|
| **Mục đích** | Tính batch multi-table, 1 output/row | Tính DAG nhiều field/row, cross-row reference |
| **Cấu hình** | `ChildTableConfig` — `formula_field`, `id_field`, `output_field` | `Formula Column Name` trong Settings — auto-detect field chứa công thức |
| **Inject giá trị** | Inject cột thành LITERAL trước khi vào engine (`"qty*rate"` → `"10*100"`) | Giữ nguyên tên biến, dùng context dict |
| **Multi field/row** | 1 formula → 1 output/row | Nhiều formula field → nhiều output/row |
| **Cross-row ref** | Không hỗ trợ (đã inject literal) | Hỗ trợ: `items.slug.field` → `slug__field` |
| **Phù hợp cho** | Cost Template (global formulas), simple child tables | **BOM Items — đây là path AlumGlass dùng** |

### C.1.2 Quyết định kiến trúc: Chọn Path B cho Bom Items

Lý do:
1. Mỗi dòng Bom Item cần tính **6 field độc lập**: `width`, `height`, `qty`, `so_luong_don_vi`, `tong_so_luong`, `thanh_tien`
2. Các dòng tham chiếu chéo nhau: `nep_kinh_tren.width = 2*(items.kinh_tren.width + items.kinh_tren.height)`
3. `ChildTableConfig` chỉ hỗ trợ 1 formula → 1 output/row → không đáp ứng được
4. `build_cross_ref_engine()` hỗ trợ đa field + cross-row reference + DAG tự động

**Kiến trúc mới (đã sửa từ review):**

```
Bom Items (17 dòng × 6 field = ~100 công thức)
    ↓
VariableResolver.build_cross_ref_engine()
    ↓ (normalize items.slug.field → slug__field)
FormulaEngine (1 DAG, topo sort, 1 lần calculate)
    ↓
Kết quả: {slug__field: value} cho tất cả field
    ↓
Python loop gom vào buckets (B5)
```

## C.2 BUILD_CROSS_REF_ENGINE CHO BOM ITEMS

### C.2.1 Cách thức hoạt động

`VariableResolver.build_cross_ref_engine()` đọc TẤT CẢ các field công thức trên TẤT CẢ các dòng của child table, chuẩn hóa cross-row reference, và tạo 1 `FormulaEngine` DAG duy nhất.

**Cơ chế normalize (cốt lõi):**

```python
# variable_resolver.py — _normalize()
# Input formula từ DB: "2*(items.kinh_tren.width + items.kinh_tren.height)"
# Output (chuẩn hóa):  "2*(kinh_tren__width + kinh_tren__height)"
```

`DotToSubscriptTransformer` trong parser chuyển `items.kinh_tren.width` → `items['kinh_tren']['width']`, sau đó `_normalize()` thay thế bằng `kinh_tren__width`. Engine DAG hiểu `kinh_tren__width` là 1 biến → detect dependency chính xác.

### C.2.2 Cấu hình Formula Column Name

Trong **Formula Builder Settings**, thêm các field sau vào bảng `Formula Column Name`:

| fieldname | Mô tả |
|---|---|
| `width` | Công thức tính chiều rộng |
| `height` | Công thức tính chiều cao |
| `qty` | Công thức tính số lượng |
| `rule_input_expr` | Biểu thức input cho Dynamic Item Rule |

Các field này được `build_cross_ref_engine()` auto-detect và thu thập công thức từ từng dòng.

### C.2.3 Công thức được inject vào DAG như thế nào

**Từ AL Bom Item.** Mỗi dòng Bom Item có các field chứa công thức (VD: `width = "W_mm"`, `qty = "1"`). Engine thu thập tất cả:

```python
# Với dòng khung_ngang_tren:
#   width="W_mm"              → formula: {"name": "khung_ngang_tren__width", "formula": "W_mm"}
#   qty="1"                   → formula: {"name": "khung_ngang_tren__qty", "formula": "1"}
#   so_luong_don_vi (từ FS)  → formula: {"name": "khung_ngang_tren__so_luong_don_vi", 
#                                          "formula": "lookup_calc_pattern(khung_ngang_tren__calc_pattern, khung_ngang_tren__width, 0, khung_ngang_tren__trong_luong_rieng)"}
#   tong_so_luong (từ FS)    → formula: {"name": "khung_ngang_tren__tong_so_luong", 
#                                          "formula": "khung_ngang_tren__so_luong_don_vi * khung_ngang_tren__qty"}
#   thanh_tien (từ FS)       → formula: {"name": "khung_ngang_tren__thanh_tien", 
#                                          "formula": "khung_ngang_tren__tong_so_luong * khung_ngang_tren__don_gia"}
```

### C.2.4 Cú pháp tham chiếu — 3 hình thức được hỗ trợ

| Cú pháp | Ví dụ | Cơ chế |
|---|---|---|
| `<table>.<slug>.<field>` | `items.kinh_tren.width` | `DotToSubscriptTransformer` → `items['kinh_tren']['width']` → normalize → `kinh_tren__width` |
| `<table>['<slug>'].<field>` | `items['kinh_tren'].width` | `ChildTableRows.__getitem__` string lookup |
| `<table>[<idx>].<field>` | `items[0].width` | `ChildTableRows.__getitem__` int index → dict → `.width` attr |

**Lưu ý:** Với Path B (build_cross_ref_engine), dùng form `<table>.<slug>.<field>` là chuẩn và khuyến nghị cho mọi công thức trong Bom Item.

### C.2.5 Code build engine cho Bom Items

```python
# alumglass/engine/bom_engine.py
from formula_builder.api.variable_resolver import VariableResolver, ScopeContext
from formula_builder.formula_utils import FormulaEngine
from alumglass.engine.handlers import lookup_calc_pattern


def build_bom_engine(bom_items, row_literals, user_inputs, calc_rules, global_vars):
    """Xây FormulaEngine cho Bom Items dùng build_cross_ref_engine pattern.
    
    Args:
        bom_items: List[Dict] — danh sách AL Bom Item (đã resolve item qua Rule)
        row_literals: Dict[slug, Dict] — {slug: {trong_luong_rieng, don_gia, calc_pattern, ...}}
        user_inputs: Dict — W_mm, H_mm, n_canh, ...
        calc_rules: Dict — OFFSET_FRAME, OFFSET_GLASS, ...
        global_vars: Dict — VAT_RATE, NC_SX_PCT, ...
    
    Returns:
        (FormulaEngine, Dict[str, Any]) — engine và inputs dict sẵn sàng để calculate()
    """
    formulas = []
    inputs = {}
    
    # 1. Inputs từ user + rules + global vars
    inputs.update(user_inputs)
    inputs.update(calc_rules)
    inputs.update(global_vars)
    
    # 2. Duyệt từng Bom Item, thu thập công thức
    for item in bom_items:
        slug = item["slug"]
        literals = row_literals.get(slug, {})
        
        # Inject literal values với naming slug__field
        for key in ("trong_luong_rieng", "don_gia", "calc_pattern",
                     "glass_thick", "glass_type"):
            if key in literals:
                inputs[f"{slug}__{key}"] = literals[key]
        
        # Thu thập công thức từ Bom Item fields
        formula_fields = {
            "width": item.get("width"),
            "height": item.get("height"),
            "qty": item.get("qty"),
        }
        for field_name, expr in formula_fields.items():
            if expr and str(expr).strip():
                normalized = _normalize_cross_ref(expr)
                formulas.append({
                    "name": f"{slug}__{field_name}",
                    "formula": normalized,
                })
        
        # Công thức từ Formula Set BOM_LINE
        so_luong_don_vi_expr = (
            f"lookup_calc_pattern({slug}__calc_pattern, "
            f"{slug}__width or 0, {slug}__height or 0, "
            f"{slug}__trong_luong_rieng or 0)"
        )
        formulas.append({"name": f"{slug}__so_luong_don_vi", "formula": so_luong_don_vi_expr})
        formulas.append({"name": f"{slug}__tong_so_luong", 
                         "formula": f"{slug}__so_luong_don_vi * ({slug}__qty or 1)"})
        formulas.append({"name": f"{slug}__thanh_tien",
                         "formula": f"{slug}__tong_so_luong * ({slug}__don_gia or 0)"})
    
    # 3. Tạo FormulaEngine với custom_functions
    engine = FormulaEngine(
        formulas=formulas,
        on_error="raise",
        deterministic=True,
        safe_funcs={"lookup_calc_pattern": lookup_calc_pattern},
    )
    
    return engine, inputs


def _normalize_cross_ref(expr: str) -> str:
    """Chuẩn hóa cross-row reference: items.<slug>.<field> → <slug>__<field>.
    
    VD: "2*(items.kinh_tren.width + items.kinh_tren.height)"
      → "2*(kinh_tren__width + kinh_tren__height)"
    """
    import re
    # Pattern: items.<slug>.<field>
    def _replace(m):
        return f"{m.group(1)}__{m.group(2)}"
    return re.sub(r'items\.(\w[\w-]*)\.(\w+)', _replace, expr)
```

### C.2.6 So sánh với thiết kế cũ (formula_expr)

| Tiêu chí | Thiết kế cũ (formula_expr) | Thiết kế mới (multi field formula) |
|---|---|---|
| **Cơ chế** | Gộp nhiều công thức vào 1 field `formula_expr` qua `; ` | Mỗi field width/height/qty là 1 công thức riêng |
| **Engine path** | FlexibleFormulaEngine + ChildTableConfig | FormulaEngine trực tiếp |
| **Multi output/row** | Không khả thi (1 formula/row) | Có — mỗi field là 1 formula name riêng |
| **Cross-row ref** | Không hoạt động (đã inject literal) | Hoạt động — normalize `items.slug.field` → `slug__field` |
| **Vì sao bỏ** | `ast.parse(mode='eval')` không parse được `;` (statement separator) | Đây là path đúng của FB |

```python
# alumglass/engine/cost_engine.py
from formula_builder.flexible_formula_engine import FlexibleFormulaEngine, EngineConfig


def run_cost_template(buckets: dict, user_inputs: dict, calc_rules: dict,
                      global_vars: dict, cost_template_lines: list):
    """Tính Cost Template → GIA_VAT dùng FlexibleFormulaEngine.
    
    Args:
        buckets: {VL_NHOM: 4895431, VL_KINH: 6330980, ...} — từ B5 gom bucket
        user_inputs: W_mm, H_mm, ...
        calc_rules: OFFSET_FRAME, ...
        global_vars: VAT_RATE, NC_SX_PCT, ...
        cost_template_lines: List[Dict] — dòng AL Cost Template Line
    
    Returns:
        CalculationResult — .values chứa GIA_VAT, GIA_BAN, TONG_VL, ...
    """
    # Merge tất cả inputs
    cost_inputs = {}
    cost_inputs.update(user_inputs)
    cost_inputs.update(calc_rules)
    cost_inputs.update(global_vars)
    cost_inputs.update(buckets)  # VL_NHOM, VL_KINH, VL_VTP, VL_PK
    
    # Xây global_formulas từ Cost Template
    global_formulas = []
    for line in cost_template_lines:
        global_formulas.append({
            "name": line["line_code"],      # VD: TONG_VL, NC_SX, GIA_VAT
            "formula": line["calc_formula"],  # VD: "VL_NHOM + VL_KINH + VL_VTP + VL_PK"
        })
    
    config = EngineConfig(
        global_formulas=global_formulas,
        extra_context=cost_inputs,
        on_error="raise",
        deterministic=True,
    )
    
    engine = FlexibleFormulaEngine(config)
    result = engine.calculate(cost_inputs)
    
    return result  # result.values["GIA_VAT"] = 22,717,289
```

### C.4.1 lookup_calc_pattern (dispatch table thuần — không gọi ngược engine)

```python
# alumglass/formula_handlers.py
_AL_CALC_PATTERNS = {}

def lookup_calc_pattern(calc_pattern_code, width=None, height=None, trong_luong_rieng=None):
    """Tính số lượng đơn vị theo 1 trong 4 pattern cố định.

    Hàm này được đăng ký vào custom_functions của FlexibleFormulaEngine,
    chạy TỪ BÊN TRONG một lượt calculate() đang xử lý DAG.
    KHÔNG được gọi ngược lại engine — đây là lỗi kiến trúc đã từng xảy ra.

    Chỉ dùng dispatch table Python thuần, không engine con.
    """
    w = (width or 0) / 1000.0
    h = (height or 0) / 1000.0
    tlr = trong_luong_rieng or 0

    if calc_pattern_code == "LENGTH_TO_WEIGHT":
        return w * tlr
    if calc_pattern_code == "AREA":
        return w * h
    if calc_pattern_code == "LENGTH_ONLY":
        return w
    if calc_pattern_code == "COUNT":
        return 1

    raise ValueError(f"calc_pattern '{calc_pattern_code}' chưa được hỗ trợ. "
                     f"Các pattern hiện có: LENGTH_TO_WEIGHT, AREA, LENGTH_ONLY, COUNT")
```

### C.4.2 Price lookup (đọc Item Price theo composite key)

```python
def resolve_price_attrs(line, inputs):
    """Nguồn sự thật duy nhất cho price attrs của dòng NHOM.

    Args:
        line: Dict — AL Bom Item (slug, line_type, price_attrs_override...)
        inputs: Dict — tất cả biến (mau_nhom, xuat_xu_nhom...)

    Returns:
        Dict hoặc None — composite key attributes
    """
    # Nếu có override (trường hợp đặc biệt)
    if line.get("price_attrs_override"):
        return json.loads(line["price_attrs_override"])

    # NHOM mặc định: dùng inputs chung từ Variable Set
    if line["line_type"] in ("NHOM", "THEP", "INOX"):
        return {
            "color": inputs.get("mau_nhom"),
            "source": inputs.get("xuat_xu_nhom"),
            "thickness": inputs.get("do_day_nhom"),
            "surface": inputs.get("be_mat_nhom"),
        }

    # PK: dùng finish/material (nếu có)
    if line["line_type"] == "PHU_KIEN":
        finish = line.get("accessory_finish")
        material = line.get("accessory_material")
        if finish or material:
            return {"finish": finish, "material": material}

    return None


def batch_price_lookup(base_items, price_list, attrs_map):
    """Batch query Item Price với composite key — chỉ 1 query SQL duy nhất.

    Args:
        base_items: list[str] — item_code đại diện (NHOM-XINGFA, ...)
        price_list: str — tên Price List
        attrs_map: dict — {color, source, thickness, surface}

    Returns:
        dict: {base_item: price} — ví dụ {"NHOM-XINGFA": 113000}

    Log error nếu có base_item không tìm thấy giá.
    """
    if not base_items:
        return {}

    filters = {"price_list": price_list, "item_code": ["in", base_items]}
    if attrs_map.get("color"):
        filters["custom_mau_sac"] = attrs_map["color"]
    if attrs_map.get("source"):
        filters["custom_xuat_xu"] = attrs_map["source"]
    if attrs_map.get("thickness"):
        filters["custom_do_day"] = attrs_map["thickness"]
    if attrs_map.get("surface"):
        filters["custom_be_mat"] = attrs_map["surface"]

    prices = frappe.db.get_all(
        "Item Price",
        filters=filters,
        fields=["item_code", "price_list_rate"],
    )

    result = {p.item_code: p.price_list_rate for p in prices}

    # Cảnh báo nếu base_item không có giá
    for item in base_items:
        if item not in result:
            frappe.log_error(
                f"Không tìm thấy Item Price cho {item} với filter {filters}",
                "AlumGlass Price Lookup",
            )

    return result
```

### C.4.3 Dynamic Item Rule Resolver

```python
def resolve_dynamic_item_rule(rule_code, input_value):
    """Tra AL Dynamic Item Rule -> item_code.

    Hỗ trợ 2 loại rule:
    - THRESHOLD: so sánh giá trị số trong khoảng (from_value, to_value)
    - LOOKUP: so sánh key chính xác

    Args:
        rule_code: str — mã rule (VD: RULE-NEP-GLASSTHICK)
        input_value: float hoặc str — giá trị input

    Returns:
        str: item_code được chọn, hoặc None nếu không match
    """
    rule = frappe.get_doc("AL Dynamic Item Rule", rule_code)

    if rule.rule_type == "THRESHOLD":
        val = float(input_value)
        for row in rule.threshold_rows:
            if float(row.from_value) <= val <= float(row.to_value):
                return row.result_item

    elif rule.rule_type == "LOOKUP":
        key = str(input_value)
        for row in rule.lookup_rows:
            if row.key_field == key:
                return row.result_item

    return None
```

### C.4.5 DataSourceResolver — Batch Query cho Cost Bucket (FB v31)

**Vấn đề:** B2 hiện tại dùng 4-5 đoạn code batch query rời rạc: 1 đoạn cho Item weight, 1 đoạn cho Item Price composite, 1 đoạn cho Glass Master, 1 đoạn cho Dynamic Rule. Mỗi khi thêm Cost Bucket mới có nguồn data mới → phải sửa code B2.

**Giải pháp:** Dùng `BatchBindingResolver` của FB v31 — kiến trúc **Collect → Group → Execute → Inject**:

```
┌─ DataSourceResolver (AlumGlass thin layer) ───────────────────────────┐
│                                                                        │
│  resolve_all(bom_items, inputs, bucket_defs):                          │
│                                                                        │
│    1. COLLECT: Duyệt AL Cost Bucket definitions                       │
│       → Thu thập TẤT CẢ data sources cần fetch                        │
│       → Mỗi bucket có source_type + source_config                     │
│                                                                        │
│    2. BUILD BINDINGS: Chuyển bucket definitions                       │
│       → List[Formula Variable Binding dict]                           │
│       → Mỗi Bom Item có thể sinh nhiều bindings                       │
│                                                                        │
│    3. DELEGATE TO FB: Gọi BatchBindingResolver.resolve_all_batch()    │
│       → FB tự động gom nhóm, batch query, cache                       │
│       → 4-5 queries thay vì 34-50 queries                             │
│                                                                        │
│    4. INJECT: Chuyển kết quả về row_literals                          │
│       → {slug__trong_luong_rieng: 1.257, slug__don_gia: 113000, ...}  │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

**Code mẫu — DataSourceResolver trong AlumGlass:**

```python
# alumglass/engine/data_source_resolver.py (MỚI — ~80 dòng)
import json
from formula_builder.api.batch_binding_resolver import BatchBindingResolver

class DataSourceResolver:
    """Resolve data cho Cost Buckets dùng FB BatchBindingResolver.

    AlumGlass chỉ cần:
    1. Định nghĩa Cost Bucket → source_type + source_config
    2. Gọi resolve_all()
    3. Nhận row_literals

    KHÔNG code batch query, KHÔNG code cache, KHÔNG code transform.
    Tất cả do FB đảm nhiệm.
    """

    def __init__(self, cache_ttl: int = 300):
        self.fb_resolver = BatchBindingResolver(cache_ttl=cache_ttl)

    def resolve_all(self, bom_items: list, inputs: dict,
                    bucket_definitions: dict) -> dict:
        """Resolve tất cả data sources cho mọi Cost Buckets.

        Returns:
            row_literals: {slug__trong_luong_rieng: float,
                           slug__don_gia: float,
                           slug__glass_thick: float, ...}
        """
        # 1. Build bindings từ Cost Bucket definitions
        bindings = self._build_bindings(bucket_definitions, bom_items, inputs)

        # 2. Ủy thác cho FB — tự động batch, cache, transform
        resolved = self.fb_resolver.resolve_all_batch(
            bindings, doc=None, pre_resolved=inputs,
        )

        # 3. Convert về row_literals format
        return self._to_row_literals(resolved, bom_items)

    def _build_bindings(self, bucket_defs, bom_items, inputs):
        """Chuyển Cost Bucket definitions → Formula Variable Binding dicts."""
        bindings = []
        for bucket_code, defn in bucket_defs.items():
            source_type = defn.get("source_type", "aggregate_from_items")
            source_config = defn.get("source_config", {})

            if source_type == "aggregate_from_items":
                # Mỗi Bom Item trong bucket → các bindings cho pre-fetch
                for item in bom_items:
                    if item.get("cost_bucket") != bucket_code:
                        continue
                    bindings += self._build_item_bindings(
                        item, source_config.get("pre_fetch", []), inputs
                    )
            elif source_type in ("doctype_query", "custom_function",
                                 "pipeline", "conditional", "fallback_chain"):
                # Bucket-level binding: resolve toàn bộ bucket trong 1 query
                bindings.append({
                    "variable_name": bucket_code,
                    "source_type": source_type,
                    "source_config": json.dumps(source_config),
                    "data_type": defn.get("data_type", "Currency"),
                    "default_value": "0",
                })
        return bindings

    def _build_item_bindings(self, item, pre_fetch_configs, inputs):
        """Sinh bindings cho 1 Bom Item từ pre_fetch config."""
        bindings = []
        slug = item["slug"]
        for fetch in pre_fetch_configs:
            # Resolve template variables trong config
            cfg = dict(fetch)
            for key, val in cfg.items():
                if isinstance(val, str) and "{inputs." in val:
                    cfg[key] = val.format(inputs=inputs)
                elif isinstance(val, str) and "{item." in val:
                    cfg[key] = val.format(item=item)

            bindings.append({
                "variable_name": f"{slug}__{fetch['target_field']}",
                "source_type": fetch["source_type"],
                "source_config": json.dumps(cfg),
                "data_type": fetch.get("data_type", "Float"),
                "batch_group": fetch.get("batch_group", ""),
            })
        return bindings

    def _to_row_literals(self, resolved, bom_items):
        """Convert flat resolved dict → row_literals theo slug."""
        row_literals = {}
        for item in bom_items:
            slug = item["slug"]
            row_literals.setdefault(slug, {})
            # Extract all {slug}__{field} keys
            prefix = f"{slug}__"
            for key, val in resolved.items():
                if key.startswith(prefix):
                    field = key[len(prefix):]
                    row_literals[slug][field] = val
        return row_literals
```

```python
        self.b3_build_bom_engine()       # ← MỚI: build FormulaEngine
        self.b4_calculate_bom_items()    # ← MỚI: gọi engine.calculate()

    def b0_version_pinning(self):

    # ==================== Phase B1: Gather Inputs ====================

    def b1_gather_inputs(self):
        """Thu thập input từ Quotation Item + Global Variables + hằng số."""
        qi = self.quotation_item

        # 1. Input từ Quotation
        self.inputs = {
            "W_mm": qi.al_W_mm,
            "H_mm": qi.al_H_mm,
            "mau_nhom": qi.al_mau_nhom,
        }
        if qi.al_bom_vars:
            self.inputs.update(json.loads(qi.al_bom_vars))

        # 2. Global variables (FB's Formula Global Variable)
        global_vars = frappe.get_all(

            filters={"is_active": 1, "value_source": "CONSTANT"},
            fields=["var_name", "constant_value"],
        )
        for gv in global_vars:
            try:
                self.inputs[gv.var_name] = float(gv.constant_value)
            except (TypeError, ValueError):
                self.inputs[gv.var_name] = gv.constant_value

        # 3. AL Calculation Rule (hằng số offset)
        rules = frappe.get_all(
            "AL Calculation Rule",
            filters={"rule_type": "CONSTANT"},
            fields=["rule_code", "constant_value"],

            try:
                self.inputs[r.rule_code] = float(r.constant_value)
            except (TypeError, ValueError):

    # ==================== Phase B2: Pre-fetch Master Data ====================
    #  THAY ĐỔI LỚN (v28.2): Dùng FB BatchBindingResolver thay vì
    #  hardcode 4-5 đoạn batch query rời rạc.
    #
    #  DataSourceResolver (AlumGlass thin layer ~80 dòng) ủy thác cho FB:
    #    - Gom nhóm query (Collect → Group → Execute)
    #    - Cache (Redis + per-request)
    #    - Transform (multiply, divide, formula, round, cast)
    #    - 4-5 queries thay vì 34-50 queries (-90%)
    #
    #  Khi thêm Cost Bucket mới: chỉ cần thêm 1 dòng trong AL Cost Bucket
    #  (source_type + source_config), KHÔNG cần sửa code B2.

    def b2_prefetch_master_data(self):
        """Pre-fetch TẤT CẢ master data qua FB BatchBindingResolver.

        So với b2_prefetch_master_data cũ (85 dòng hardcode):
        - Cũ: 4-5 đoạn batch query riêng, mỗi loại data 1 cách fetch
        - Mới: 1 dòng gọi DataSourceResolver.resolve_all()
        - Code B2: 85 dòng → 15 dòng (-82%)
        """
        from alumglass.engine.data_source_resolver import DataSourceResolver

        resolver = DataSourceResolver(cache_ttl=300)
        self.row_literals = resolver.resolve_all(
            bom_items=self.bom_items,
            inputs=self.inputs,
            bucket_definitions=self._load_cost_bucket_definitions(),
        )
        # → 4-5 batch queries (Item weight, Item Price, Glass Master, Rules)
        # → Tự động cache, tự động transform
        # → Kết quả: {slug__trong_luong_rieng, slug__don_gia, slug__glass_thick, ...}

    def _load_cost_bucket_definitions(self):
        """Đọc Cost Bucket definitions từ DB.

        Mỗi bucket có source_type + source_config định nghĩa nguồn data.
        Khai báo 1 lần trong AL Cost Bucket, dùng cho mọi BOM.
        """
        buckets = frappe.get_all(
            "AL Cost Bucket",
            fields=["bucket_code", "source_type", "source_config",
                    "depends_on", "batch_group"],
        )
        result = {}
        for b in buckets:
            source_config = {}
            if b.source_config:
                try:
                    source_config = json.loads(b.source_config)
                except (json.JSONDecodeError, TypeError):
                    pass
            depends_on = []
            if b.depends_on:
                try:
                    depends_on = json.loads(b.depends_on)
                except (json.JSONDecodeError, TypeError):
                    pass
            result[b.bucket_code] = {
                "source_type": b.source_type or "aggregate_from_items",
                "source_config": source_config,
                "depends_on": depends_on,
                "batch_group": b.batch_group or "",
            }
        return result

    def _resolve_rule_input(self, item, row_literals):
        """Tìm giá trị input cho Dynamic Item Rule từ cross-row reference.

        VD: rule_input_expr = "items.kinh_tren.glass_thick"
        → resolve ra 24 (từ row_literals["kinh_tren"]["glass_thick"])
        """
        if not item.get("rule_input_expr"):
            return None

        expr = item["rule_input_expr"].strip()
        m = re.match(r'items\.(\w[\w-]*)\.(\w+)', expr)
        if m:
            ref_slug, ref_field = m.group(1), m.group(2)
            return row_literals.get(ref_slug, {}).get(ref_field)

        return item.get("rule_input_value")

    # ==================== Phase B3: Build Bom Engine ====================
    #  THAY ĐỔI LỚN: Dùng FormulaEngine trực tiếp thay vì 
    #  FlexibleFormulaEngine + ChildTableConfig + formula_expr

    def b3_build_bom_engine(self):
        """Xây FormulaEngine từ Bom Items với cross-row reference.
        
        Cơ chế:
        1. Mỗi field (width/height/qty) trên mỗi dòng → 1 formula name: {slug}__{field}
        2. Cross-row reference được normalize: items.kinh_tren.width → kinh_tren__width
        3. Literal values (don_gia, trong_luong_rieng) inject vào inputs với naming {slug}__{key}
        4. Engine DAG tự detect dependency → topo sort → evaluate
        """
        formulas = []
        self.bom_inputs = dict(self.inputs)  # Copy inputs từ B1

        for item in self.bom_items:
            slug = item["slug"]
            literals = self.row_literals.get(slug, {})

            # Inject literal values vào inputs
            for key in ("trong_luong_rieng", "don_gia", "calc_pattern",
                         "glass_thick", "glass_type"):
                if key in literals:
                    self.bom_inputs[f"{slug}__{key}"] = literals[key]

            # Thu thập công thức từ Bom Item fields
            formula_fields = {
                "width": item.get("width"),
                "height": item.get("height"),
                "qty": item.get("qty"),
            }
            for field_name, expr in formula_fields.items():
                if expr and str(expr).strip():
                    normalized = _normalize_cross_ref(str(expr))
                    formulas.append({
                        "name": f"{slug}__{field_name}",
                        "formula": normalized,
                    })

            # Công thức từ Formula Set BOM_LINE
            formulas.append({
                "name": f"{slug}__so_luong_don_vi",
                "formula": (
                    f"lookup_calc_pattern({slug}__calc_pattern, "
                    f"({slug}__width or 0), ({slug}__height or 0), "
                    f"({slug}__trong_luong_rieng or 0))"
                ),
            })
            formulas.append({
                "name": f"{slug}__tong_so_luong",
                "formula": f"{slug}__so_luong_don_vi * ({slug}__qty or 1)",
            })
            formulas.append({
                "name": f"{slug}__thanh_tien",
                "formula": f"{slug}__tong_so_luong * ({slug}__don_gia or 0)",
            })

        self.bom_engine = FormulaEngine(
            formulas=formulas,
            on_error="raise",
            deterministic=True,
            safe_funcs={
                "lookup_calc_pattern": lookup_calc_pattern,
            },
        )

    # ==================== Phase B4: Calculate Bom Items ====================

    def b4_calculate_bom_items(self):
        """Gọi FormulaEngine để tính toàn bộ Bom Items trong 1 DAG.
        
        Engine tự động:
        1. Topo sort ~100 formula names
        2. Detect cross-row dependency (kinh_tren__width → nep_kinh_tren__width)
        3. Evaluate → flat dict {slug__field: value}
        """
        self.bom_result = self.bom_engine.calculate(self.bom_inputs)

        # Kiểm tra lỗi
        if hasattr(self.bom_engine, 'last_errors') and self.bom_engine.last_errors:
            AlumGlassErrorHandler.handle(self.bom_engine.last_errors)

    # ==================== Phase B5: Gom Cost Bucket ====================

    def b5_gom_cost_bucket(self):
        """Gom thanh_tien theo cost_bucket (Python loop)."""
        buckets = defaultdict(float)
        line_results = []

        for item in self.bom_items:
            slug = item["slug"]
            thanh_tien = self.bom_result.get(f"{slug}__thanh_tien", 0)
            bucket_code = item.get("cost_bucket")

            if bucket_code:
                buckets[bucket_code] += thanh_tien

            line_results.append({
                "slug": slug,
                "width": self.bom_result.get(f"{slug}__width", 0),
                "height": self.bom_result.get(f"{slug}__height", 0),
                "qty": self.bom_result.get(f"{slug}__qty", 0),
                "so_luong_don_vi": self.bom_result.get(f"{slug}__so_luong_don_vi", 0),
                "tong_so_luong": self.bom_result.get(f"{slug}__tong_so_luong", 0),
                "thanh_tien": thanh_tien,
                "cost_bucket": bucket_code,
                "line_type": item.get("line_type"),
            })

        self.buckets = dict(buckets)
        self.line_results = line_results

    # ==================== Phase B6: Cost Template ====================

    def b6_cost_template(self):
        """Chạy FlexibleFormulaEngine cho Cost Template → GIA_VAT.
        
        ĐÂY LÀ CHỖ DÙNG FlexibleFormulaEngine ĐÚNG: Cost Template là 
        global formulas thuần túy, không cần ChildTableConfig.
        """
        cost_inputs = dict(self.inputs)
        for bucket_code, value in self.buckets.items():
            cost_inputs[bucket_code] = value

        # Xây global_formulas từ AL Cost Template
        global_formulas = []
        for line in self.cost_lines:
            global_formulas.append({
                "name": line["line_code"],
                "formula": line["calc_formula"],
            })

        cost_config = EngineConfig(
            global_formulas=global_formulas,
            extra_context=cost_inputs,
            on_error="raise",
            deterministic=True,
        )

        engine2 = FlexibleFormulaEngine(cost_config)
        self.cost_result = engine2.calculate(cost_inputs)

        if self.cost_result.errors:
            AlumGlassErrorHandler.handle(self.cost_result)

        # Kết quả cuối cùng
        self.result = {
            "GIA_VAT": self.cost_result.values.get("GIA_VAT", 0),
            "GIA_BAN": self.cost_result.values.get("GIA_BAN", 0),
            "DON_GIA_M2": self.cost_result.values.get("DON_GIA_M2", 0),
            "TONG_VL": self.buckets.get("TONG_VL", 0),
            "VL_NHOM": self.buckets.get("VL_NHOM", 0),
            "VL_KINH": self.buckets.get("VL_KINH", 0),
            "VL_VTP": self.buckets.get("VL_VTP", 0),
            "VL_PK": self.buckets.get("VL_PK", 0),
            "line_results": self.line_results,
            "cost_details": self.cost_result.values,
        }

    # ==================== Phase B7: Save Snapshot ====================

    def b7_save_snapshot(self):
        """Lưu child table + ConfigSnapshot."""
        qi = frappe.get_doc("Quotation Item", self.qi_name)
        qi.al_bom_version = self.bom_version_id
        qi.al_vl_nhom = self.buckets.get("VL_NHOM", 0)
        qi.al_vl_kinh = self.buckets.get("VL_KINH", 0)
        qi.al_vl_vtp = self.buckets.get("VL_VTP", 0)
        qi.al_vl_pk = self.buckets.get("VL_PK", 0)
        qi.al_tong_vl = self.buckets.get("TONG_VL", 0)
        qi.al_gia_thanh = self.cost_result.values.get("GIA_THANH", 0)

        self.config_snapshot = create_alumglass_snapshot(
```

```python
def resolve_effective_version(doctype, parent_field, at_date=None):
    """Tìm version hiệu lực tại thời điểm.

    Args:
        doctype: AL BOM Version hoặc AL Dynamic Item Rule Version
        parent_field: Tên field trỏ về parent (bom/rule)

        order_by="valid_from desc",
```

```python
def material_check_hook(doc, method):
    """Hook validate AL Cutting Plan: chặn Confirm nếu chưa đủ hàng.

    Điều kiện (đủ cả 3 mới cho Confirm):
    1. Batch tồn kho đủ số lượng
    2. Deposit đã được thanh toán (Sales Order status check)
    3. PO / Subcontracting Order đã được đặt cho phần thiếu

    if doc.status == "Confirmed" and not doc.material_check_passed:
        # Điều kiện 1: Batch tồn kho
        for line in doc.cutting_lines:
            if line.batch_no:
                batch_qty = frappe.db.get_value("Batch", line.batch_no, "batch_qty")
                if (batch_qty or 0) < line.qty:
                    frappe.throw(
                        f"Thiếu tồn kho cho {line.item_code} / batch {line.batch_no}: "
                        f"cần {line.qty}, còn {batch_qty}"

        # Điều kiện 2: Deposit đã trả
        so = frappe.get_doc("Sales Order", doc.sales_order)
        if so.per_billed < 30:
            frappe.throw(
                f"Chưa đủ điều kiện cắt: khách hàng mới thanh toán "
                f"{so.per_billed}% (cần tối thiểu 30% deposit)"
            )

        doc.material_check_passed = 1
```

### Giải thích cách đọc bảng

**1. NHOM đơn giản (dòng 10-40):** `width` lấy từ input W_mm, `qty` là hằng số. Không tham chiếu chéo. VD dòng 10: width=2400, qty=1, item=XF55-KB-20, tra giá qua NHOM-XINGFA.

**2. NHOM chia cánh (dòng 50-60):** `width` tính theo n_canh, `qty` = 2*n_canh. VD dòng 50: width=2400/2-48=1152mm, qty=4.

**3. KINH (dòng 70-80):** Có cả `width` và `height` (tính diện tích). VD dòng 70: width=2300, height=550, qty=1 -> diện tích=1.265 m2.

**4. Cross-row + Dynamic Rule (dòng 90-120):** `width` tham chiếu kết quả của dòng khác. `rule_input_expr` xác định input cho Dynamic Item Rule.
- Dòng 90: `width = 2*(items.kinh_tren.width + items.kinh_tren.height)` = 2*(2300+550)=5700
- `rule_input_expr = items.kinh_tren.glass_thick` -> resolve ra 24 -> Rule chọn C3211-20

**5. VTP có cross-row (dòng 130):** `width` = tổng chu vi khung (24+24+2*26=10000mm) -> LENGTH_ONLY -> 10m gioăng.

**6. COUNT (dòng 140-170):** `calc_pattern=COUNT` -> so_luong_don_vi luôn = 1. `qty` là số lượng thực tế.

```python
def take_snapshot_on_publish(doc, method):
    """Khi AL BOM Version chuyển Published, snapshot Bom Items + Cost Template.

    Hook: on_update, nếu workflow_state thay đổi thành Published.
    """
    if doc.workflow_state != "Published":
        return

    # Chỉ snapshot nếu chưa có
    if doc.profile_set_snapshot and doc.cost_template_snapshot:
        return

    bom = frappe.get_doc("AL BOM", doc.bom)
    bom_set = frappe.get_doc("AL Bom Set", bom.bom_set)

    # Snapshot Bom Items
    items_snapshot = []
    for item in bom_set.al_bom_items:
        items_snapshot.append({
            "slug": item.slug,
            "line_type": item.line_type,
            "width": item.width,
            "height": item.height,
            "qty": item.qty,
            "item_selection_mode": item.item_selection_mode,
            "item_code": item.item_code,
            "item_rule": item.item_rule,
            "cost_bucket": item.cost_bucket,
            "calc_pattern": item.calc_pattern,
            "price_base_item": item.price_base_item,
            "price_type": item.price_type,
            "fixed_price": item.fixed_price,
            # formula_expr đã deprecated — không cần snapshot
        })

    doc.profile_set_snapshot = json.dumps(items_snapshot, default=str)

    # Snapshot Cost Template
    cost_template = frappe.get_doc("AL Cost Template", bom.default_cost_template)
    cost_snapshot = []
    for line in cost_template.al_lines:
        cost_snapshot.append({
            "line_code": line.line_code,
            "calc_formula": line.calc_formula,
            "cost_bucket": line.cost_bucket,
            "is_subtotal": line.is_subtotal,
        })
    doc.cost_template_snapshot = json.dumps(cost_snapshot, default=str)

    doc.db_set({
        "profile_set_snapshot": doc.profile_set_snapshot,
        "cost_template_snapshot": doc.cost_template_snapshot,
    })
```

```python
def take_rule_snapshot_on_publish(doc, method):
    """Khi AL Dynamic Item Rule Version Published, snapshot nội dung Rule.

    Hook: on_update
    """
    if doc.workflow_state != "Published":
        return
    if doc.rule_snapshot_json:
        return

    rule = frappe.get_doc("AL Dynamic Item Rule", doc.rule)
    snapshot = {"rule_type": rule.rule_type, "rows": []}

    if rule.rule_type == "THRESHOLD":
        for row in rule.threshold_rows:
            snapshot["rows"].append({
                "from_value": float(row.from_value),
                "to_value": float(row.to_value),
                "result_item": row.result_item,
            })
    elif rule.rule_type == "LOOKUP":
        for row in rule.lookup_rows:
            snapshot["rows"].append({
                "key_field": row.key_field,
                "result_item": row.result_item,
            })

    doc.rule_snapshot_json = json.dumps(snapshot, default=str)
    doc.db_set("rule_snapshot_json", doc.rule_snapshot_json)
```

```python
    Hook: validate của AL Bom Item
    """
    slug = frappe.get_cached_doc("AL Slug Library", doc.slug)

    # Đồng bộ line_type từ AL Slug Library
    if doc.line_type != slug.line_type:
        doc.line_type = slug.line_type

    if doc.line_type == "NHOM":
        if not doc.item_code:
            frappe.throw(f"Bom Item {doc.slug}: thiếu item_code cho NHOM")
        if doc.calc_pattern != "LENGTH_TO_WEIGHT":
            frappe.throw(f"Bom Item {doc.slug} (NHOM): calc_pattern phải là LENGTH_TO_WEIGHT")
        if not doc.price_base_item:
            frappe.throw(f"Bom Item {doc.slug} (NHOM): thiếu price_base_item")

    elif doc.line_type == "KINH":
        if doc.calc_pattern != "AREA":
            frappe.throw(f"Bom Item {doc.slug} (KINH): calc_pattern phải là AREA")
        if not doc.default_glass_master:
            frappe.throw(f"Bom Item {doc.slug} (KINH): thiếu default_glass_master")
        if not doc.ctx_inject_prefix:
            frappe.throw(f"Bom Item {doc.slug} (KINH): thiếu ctx_inject_prefix")

    elif doc.line_type == "VTP":
        if doc.calc_pattern not in ("LENGTH_ONLY", "COUNT"):
            frappe.throw(f"Bom Item {doc.slug} (VTP): calc_pattern phải là LENGTH_ONLY hoặc COUNT")

    elif doc.line_type == "PK":
        if doc.calc_pattern != "COUNT":
            frappe.throw(f"Bom Item {doc.slug} (PK): calc_pattern phải là COUNT")

    # Rule mode bắt buộc có rule_input_expr
    if doc.item_selection_mode == "Rule":
        if not doc.rule_input_expr:
            frappe.throw(f"Bom Item {doc.slug} (mode=Rule): thiếu rule_input_expr")
```

### H.3.2 Step 2: Xay formulas + inputs cho FormulaEngine (B3-B4)

**Cơ chế:**
- Mỗi field (width/height/qty) trên mỗi dòng → 1 formula name: `{slug}__{field}`
- Cross-row reference được normalize: `items.kinh_tren.width` → `kinh_tren__width`
- Literal values inject vào inputs với naming `{slug}__{key}`
- Engine DAG tự detect dependency giữa các formula name

```python
import re

def _normalize_cross_ref(expr: str) -> str:
    """Chuẩn hóa cross-row reference: items.<slug>.<field> → <slug>__<field>."""
    return re.sub(r'items\.(\w[\w-]*)\.(\w+)', r'\1__\2', expr)


def build_formulas_and_inputs(items, row_literals, resolved_items,
                               user_input, calc_rules, global_vars):
    """Xây formulas list + inputs dict cho FormulaEngine.
    
    Returns:
        (List[dict], Dict) — formulas cho FormulaEngine constructor + inputs cho calculate()
    """
    formulas = []
    inputs = {}
    inputs.update(user_input)
    inputs.update(calc_rules)
    inputs.update(global_vars)

    for item in items:
        _, slug, line_type, width_expr, height_expr, qty_expr, \
            mode, item_code, bucket, calc, base = item

        # Inject literal values với naming {slug}__{field}
        for field in ("trong_luong_rieng", "don_gia", "calc_pattern"):
            if field in row_literals.get(slug, {}):
                inputs[f"{slug}__{field}"] = row_literals[slug][field]

        if line_type == "KINH":
            for field in ("glass_thick", "glass_type"):
                if field in row_literals.get(slug, {}):
                    inputs[f"{slug}__{field}"] = row_literals[slug][field]

        # Công thức width/height/qty — normalize cross-row reference
        formula_fields = {
            "width": width_expr,
            "height": height_expr,
            "qty": qty_expr,
        }
        for field_name, expr in formula_fields.items():
            if expr and str(expr).strip():
                normalized = _normalize_cross_ref(str(expr))
                formulas.append({
                    "name": f"{slug}__{field_name}",
                    "formula": normalized,
                })

        # Công thức từ Formula Set BOM_LINE
        formulas.append({
            "name": f"{slug}__so_luong_don_vi",
            "formula": (
                f"lookup_calc_pattern({slug}__calc_pattern, "
                f"({slug}__width or 0), ({slug}__height or 0), "
                f"({slug}__trong_luong_rieng or 0))"
            ),
        })
        formulas.append({
            "name": f"{slug}__tong_so_luong",
            "formula": f"{slug}__so_luong_don_vi * ({slug}__qty or 1)",
        })
        formulas.append({
            "name": f"{slug}__thanh_tien",
            "formula": f"{slug}__tong_so_luong * ({slug}__don_gia or 0)",
        })

    # Đảm bảo các dòng COUNT/LENGTH_ONLY có literal mặc định
    for item in items:
        _, slug, _, _, _, _, _, _, _, calc, _ = item
        if calc in ("LENGTH_ONLY", "COUNT"):
            if f"{slug}__trong_luong_rieng" not in inputs:
                inputs[f"{slug}__trong_luong_rieng"] = 0
            if f"{slug}__don_gia" not in inputs:
                inputs[f"{slug}__don_gia"] = 0

    return formulas, inputs
```

## H.7 THIẾT KẾ TƯƠNG LAI — CÁC KHOẢNG TRỐNG ĐÃ XÁC ĐỊNH

Các tính năng dưới đây nằm ngoài phạm vi Phase 1 (MVP BOM + tính giá). Được ghi nhận để thiết kế sau, không block tiến độ hiện tại.

### H.7.1 Panel động — vách kính nhiều ô (curtain wall)

**Vấn đề:** Vách kính lớn chia thành N ô (panel), N được tính từ formula lúc runtime. Model child table tĩnh của FormulaEngine không hỗ trợ sinh dòng động.

**Hướng giải quyết (thiết kế sơ bộ):**
1. B4 trả về `panel_count = N` từ formula `(n_do_dung+1) * (n_do_ngang+1)`
2. Python loop sau B4 sinh N dòng ảo (virtual rows) với slug `{prefix}_panel_{i}`
3. Mỗi panel kế thừa `glass_thick`, `glass_type` từ dòng cha
4. Gọi `calculate_batch()` của FormulaEngine cho N panel (batch mode, 1 DAG)
5. Gom kết quả panel vào bucket như bình thường

**Lưu ý:** Đây là bài toán phức tạp nhất trong AlumGlass ERP. Cần thiết kế riêng ở Phase 2 (cùng lúc với Cutting Plan).

### H.7.2 Tối ưu cắt (Cutting Optimization)

**Hiện trạng:** DocType `AL Cutting Plan` và `AL Cutting Standard` đã có schema. Thuật toán cắt tối ưu (1D Bin Packing / FFD cho nhôm, 2D Guillotine cho kính) chưa được implement.

**Hướng giải quyết:**
- 1D Cutting (nhôm): First Fit Decreasing (FFD) trên thanh 6000mm, tracking offcut qua Serial No
- 2D Cutting (kính): Guillotine cut trên tấm jumbo (3210×2250), thuật toán shelf hoặc skyline
- Hao hụt miter 45°: thêm field `miter_waste_mm` vào `AL Cutting Standard` — với cắt góc 45°, hao hụt = `profile_width * tan(22.5°) * 2` mỗi đầu cắt
- Các thuật toán này là code Python riêng, **không liên quan đến Formula Builder**

### H.7.3 Nhôm 2 màu (dual-color profile)

**Vấn đề:** Profile 2 mặt sơn khác màu (VD: ngoài xám, trong trắng) — phổ biến ở nhà cao tầng. Batch chỉ mang 1 `al_color`.

**Hướng giải quyết:**
- Thêm Item Variant hoặc custom field `al_outer_color` / `al_inner_color`
- Khi tính giá: giá nhôm 2 màu = giá màu ngoài (đắt hơn), vì chỉ cần sơn 1 mặt màu đặc biệt
- MRP Lite gộp nhu cầu theo cả 2 màu

### H.7.4 Mở rộng calc_pattern thứ 5 (nếu cần)

Dispatch table 4 pattern (LENGTH_TO_WEIGHT / AREA / LENGTH_ONLY / COUNT) là **hardcode có chủ đích** (nguyên tắc #19). Nếu tương lai cần pattern mới (VD: tính theo thể tích cho phào đúc), cần sửa code Python ở `lookup_calc_pattern()` — **không cấu hình được qua UI**. Ghi chú rõ trong tài liệu vận hành để tránh kỳ vọng sai.

### H.8.7 So sánh: Trước và sau khi dùng tính năng linh hoạt

| Tiêu chí | Trước (hardcode) | Sau (FB v31 + khai báo) |
|---|---|---|
| **Thêm Cost Bucket mới** | Sửa orchestrator.py, thêm 20-30 dòng Python, deploy | Tạo 1 record AL Cost Bucket + 1 dòng Cost Template |
| **Thay đổi nguồn data** | Sửa code Python, test lại, deploy | Sửa JSON config trong AL Cost Bucket |
| **Thêm composite key** | Viết hàm batch query mới | Khai báo filters trong doctype_query |
| **Pipeline tính giá** | Code Python multi-step | 1 config pipeline JSON |
| **Giá theo product_type** | IF/ELSE trong code | 1 config conditional JSON |
| **Resilience (API→cache→default)** | Code try/except lồng nhau | 1 config fallback_chain JSON |
| **Transform (USD→VND, mm→m)** | Code Python xử lý hậu kỳ | 1 field `transform` trong source_config |
| **Cache strategy** | Tự implement Redis cache | Khai báo `cache_ttl` trong source_config |
| **Validate config** | Lỗi runtime | JSON Schema validation khi save |
| **Audit data source** | Log thủ công | FB tự động log + data lineage |
| **Thời gian thêm bucket** | 2-4 giờ (cần dev) | 5-15 phút (user tự làm) |
